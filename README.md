# 命令提示助手 · Command Helper

AstrBot 命令用法提醒插件。识别漏空格、参数粘连、未唤醒机器人和相近命令名，说明原因并给出重发示例。提醒后停止本次聊天，由用户重新发送命令。

默认使用规则提醒，也可让大模型生成一句提示。插件不会自动执行建议的命令。

## 使用示例

假设某插件注册了 `活动 报名 <用户名>`，并配置了参数格式、提示别名和加号分隔规则：

| 用户输入 | 提醒 |
| --- | --- |
| 真正 @后发送 `活动报名User_01` | 命令可能漏了空格，请重发：`活动 报名 User_01` |
| 未唤醒机器人就发送 `活动 报名 User_01` | 提醒真正 @机器人或添加当前合法唤醒前缀，并给出重发示例 |
| 真正 @后发送 `活动 报名+User_01` | 命令和参数之间的“+”应改为空格，请重发：`活动 报名 User_01` |
| 目标命令要求真实 @，用户只用了唤醒前缀 | 提醒从群成员列表选择机器人进行 @，再重发命令 |
| 真正 @后发送提示词 `报名` | 给出完整用法 `活动 报名 <用户名>`，提醒填写必填参数 |
| 真正 @后发送 `活动 报民 User_01` | 提示命令名可能有误，给出候选 `活动 报名 User_01` |

可提示的命令取决于已启用插件的注册信息和补充规则。一条输入有多个问题时，会一起指出；参数的大小写、下划线和真实 @组件会保留。格式提醒不代表业务操作成功。

## 安装

在 AstrBot 插件管理中使用以下仓库地址安装：

```text
https://github.com/timeance/astrbot_plugin_command_helper
```

- 插件标识：`astrbot_plugin_command_helper`；展示名：命令提示助手。
- 支持 AstrBot `>=4.27.3,<4.29.0`，当前仅处理 QQ／`aiocqhttp` 群消息。
- 无额外运行依赖。建议先配置一个测试群，确认提醒效果。
- 停用或卸载后恢复原消息处理流程；重载会清空提醒冷却记录。

## 识别范围

插件从运行时注册表读取已启用命令的名称、别名、命令组和参数。命令改名、启停或热重载后，提示随之更新。

- 优先修正空格并匹配最长命令；同一处理器的别名合并，最多展示 3 条候选用法。
- 没有真正 @时，只识别完整命令或格式明确的输入，不根据普通聊天猜测命令。
- 参数边界确定时才拆分粘连内容，例如中文命令后紧接 ASCII 用户名，或参数符合补充规则中的正则表达式。
- 真正 @后，可建议命令名至少 4 个非空白字符、且相差一个字符的候选。只比较命令名，不修改参数。
- 已正常命中的命令放行。合法唤醒前缀可代替 @，但目标命令明确要求真实 @时仍会提醒。
- 不重复框架已有的参数缺失、类型错误提示，不读取引用或转发中的命令。

候选需通过平台、消息类型、权限和会话范围检查。含未知自定义过滤器的命令默认跳过；插件内部手动解析的子命令和隐藏业务条件，需要补充规则。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `allowed_group_ids` | `[]` | 留空时遵循 AstrBot 当前会话范围；填写后仅在指定群提醒 |
| `cooldown_seconds` | `30` | 同平台、群、用户、命令的提醒间隔，支持 0–3600 秒 |
| `hint_mode` | `无大模型` | 无大模型／仅大模型提示／大模型+提醒 |
| `llm_provider_id` | 空字符串 | 提醒使用的模型；留空使用当前会话的聊天模型 |
| `command_overrides` | `[]` | 按插件标识和处理器方法名补充规则 |

冷却期内，同类错误不再提醒，但仍停止本次聊天。正确命令不受冷却限制。更改配置后重载插件。

### 大模型提醒

- **无大模型**：发送具体原因和重发示例。
- **仅大模型提示**：把本条输入、候选命令、用法、问题和重发示例交给模型，发送模型生成的一句提示。
- **大模型+提醒**：在同一条回复中，先发模型提示，再附上规则生成的原因和重发示例。

模型调用在范围、权限和冷却检查之后进行，不传入聊天历史，也不提供工具。模型不可用、10 秒超时、返回空白或超过 200 字时，改用规则提醒。普通聊天和冷却中的重复错误不会调用模型。

开启大模型模式后，本条输入及其参数会发送给所选模型服务，插件本身不记录这些内容。模型文字可能有误；需要附上规则生成的重发示例时，选择“大模型+提醒”。

### 补充规则

在 WebUI 的 `command_overrides` 中添加“命令用法补充”。`plugin` 使用插件 `metadata.yaml` 的 `name`，`handler` 使用处理器的 Python 方法名。以下规则对应前面的报名示例：

```json
{
  "plugin": "astrbot_plugin_example",
  "handler": "cmd_signup",
  "usage": "{command} <用户名>",
  "require_at": false,
  "argument_pattern": "[A-Za-z0-9_]{3,16}",
  "hint_aliases": ["报名"],
  "allow_plus": true,
  "allow_custom_filters": false
}
```

- `usage`：用法模板。`{command}`使用当前有效命令名；留空时按声明参数生成 `<必填参数>`、`[可选参数]`。
- `require_at`：是否必须真正 @机器人。纯文本 `@昵称`不算，需从群成员列表选择机器人。
- `argument_pattern`：完整参数的正则表达式，仅用于识别提醒，不代替业务校验。避免使用复杂回溯表达式。
- `hint_aliases`：真正 @后可触发用法建议的提示词，不会注册新命令。
- `allow_plus`：将命令和参数之间的 `+`视为误用的分隔符，不改参数内部的加号。
- `allow_custom_filters`：默认关闭。开启后，可提示含未知自定义过滤器的命令，但不会运行这些过滤器。请先确认其隐藏限制，并用 `allowed_group_ids`限定提醒范围；标准权限检查仍生效。

同一插件、同一处理器有多条规则时，最后一条生效。

## 验证与限制

0.1.1 已在 Python 3.12.14、AstrBot 4.27.3 和 4.28.0 下通过匹配、消息分派、配置解析和三种提醒模式的测试，Ruff 检查与格式检查通过。模型调用使用模拟响应验证，尚未完成真实模型服务和 QQ 群收发验收。

开发检查：

```powershell
python -m pip install -r requirements-dev.txt
# 指向已安装依赖的 AstrBot 源码，使用独立测试数据目录
$env:PYTHONPATH = "C:\src\AstrBot"
$env:ASTRBOT_ROOT = "$env:TEMP\command-helper-test"
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
python scripts/package.py
```

测试位于 `tests/`，缺少所需运行环境的集成测试会跳过。打包结果位于 `dist/`，包含安装 ZIP 和 SHA-256 校验文件。

使用前在测试群检查真实 @、同名机器人、关键词聊天插件的执行顺序和重复错误提醒。提醒器优先级为 1000，更早执行的插件或过滤器已发送的消息无法撤回。插件依赖 AstrBot 内部命令注册表，兼容范围以已验证版本为准。
